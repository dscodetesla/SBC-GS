# Віртуальний TX12 (EdgeTX USB-джойстик) для справжнього `EvdevSource` моста

Стан 2026-10-03. Позначки: **REPO** перевірено тестами цього репозиторію, **SRC** прочитано з першоджерела (EdgeTX `main`), **INF** виведено, **UNVERIFIED** не підтверджено, **HW** лише на реальному радіо. Нічого тут не бачило справжнього TX12 MKII.

## 1. Що це
`tests/sim/evdev/` створює у ядрі віртуальний пристрій, який виглядає для `bench/tx12_bridge.py --input evdev` як USB-джойстик EdgeTX (режим Classic: CH1–CH8 -> осі, 24 кнопки), і проганяє справжній `EvdevSource` та головний цикл моста. Продюсер (`vdev.py`) написаний на сирому ABI ядра зі стандартною бібліотекою, без `python-evdev`, щоб помилка бібліотеки не гасилась сама собою. Два бекенди:
- `uinput` (`/dev/uinput`): пристрій задається профілем (ім'я, id, діапазони ABS, fuzz/flat, кнопки);
- `uhid` (`/dev/uhid`): пристрій створюється зі справжнього HID-дескриптора Classic EdgeTX (байти з `usb_joystick.cpp`), а осі, діапазони, fuzz/flat і коди кнопок виводить ядро (`hid-generic`, `hid-input`), як для реального USB-радіо.
Є також офлайн-підміна модуля `evdev` у процесі (`FakeEvdevModule`): це SYNTH API `python-evdev`, її звіряють ядерні бекенди.

## 2. Запуск
- `tests/sim/evdev/run.sh --check`: офлайн, секунди; тести без ядерного пристрою (мапа, профіль, дескриптор, `EvdevSource` проти підміни, головний цикл). Тести з ядерним пристроєм дають SKIP, якщо `/dev/uinput` чи `/dev/uhid` недоступні (контейнер).
- `tests/sim/evdev/run.sh device`: ядерні тести на цій машині (потрібні `/dev/uinput`, `python-evdev`, `pymavlink`), код 77, якщо не можна.
- `tests/sim/evdev/run.sh all`: повний набір у QEMU x86_64 з ядром Ubuntu generic (вбудований `uinput`, модулі `uhid`/`hid-generic`), справжні `python-evdev` і `pymavlink`; без root (TCG/KVM). Кеш ядра спільний із `tests/sim/virt/`.
- `tests/sim/evdev/mutate.sh`: мутації на КОПІЇ.
- `vdev.py show | serve`: ручний пристрій для експериментів (лише на цій машині, нікуди не підключати).

## 3. Результати (REPO)
- `--check`: 36 тестів (3 SKIP у контейнері без `uinput`). `all` у QEMU: **61 тест, OK** (1 SKIP: немає `/usr/include/linux/input-event-codes.h` у гості), ≈220 с під TCG.
- Знахідка (важлива): раніше `bench/tx12_map.example.json` мав placeholder `-1024..1024`, центр 0, а реальний Classic-діапазон 0..2047 із центром 1024 (SRC `usb_joystick.cpp:114-115`, `limit(0, channelOutput + 1024, 2047)`). З placeholder центр стіка (сирі 1024) давав повне відхилення, 2000 мкс. Приклад виправлено на 0..2047/1024; тест `test_placeholder_range_is_dangerous_on_the_real_one` фіксує небезпеку старих значень.
- Міст тепер: бачить зникнення пристрою негайно (не через `--deadman-ms`), виконує dead-man (кадри throttle-failsafe, потім release), після відпускання виходить із кодом 4 і **ніколи** не перевідкриває шлях сам (новий пристрій міг отримати той самий `eventN`); повторне підключення не відновлює керування.
- Вибір пристрою: `evdev:id=VVVV:PPPP` або `evdev:name=<точне ім'я>`; неоднозначність чи відсутність збігу відмова, не здогад. Блок `device` у мапі (vendor/product/name) відхиляє чужий пристрій на тому ж шляху (`0x1209` / `0x4F54`, SRC `usbd_desc.c`).
- Мапа відхиляє дві осі на одному каналі, не-`ABS_*` імена, нечислові/нескінченні значення (раніше `AttributeError`).
- Перевірено: нормальна робота й межі, дві осі в одному звіті, шторм подій 10 кГц, `SYN_DROPPED` із ресинхронізацією, нерухомий стік (за дизайном лишається свіжим), зникнення й повторне підключення, відсутність прав на `/dev/input/eventN`, подвійний запуск (замок вмирає з процесом), відсутня вісь.

## 4. Профіль і походження
`profile_tx12_classic.json` має `_provenance` для кожного поля: vendor/product, діапазони осей 0..2047, початкове 1024, дескриптор, 24 кнопки: SRC; імена осей Linux, fuzz 7 і flat 127, коди кнопок: INF (правила `hid-input`, звірено з гостьовим ядром 6.8 через `uhid`); ім'я пристрою (`OpenTX <USB_NAME> Joystick`), `bcdDevice`: UNVERIFIED; частота звітів 1 кГц за відсутності RF, інакше період модуля (`docs/CONTOUR-GS.md` §3.5): HW/UNMEASURED.

## 5. Що це НЕ доводить
Реальний дескриптор і ім'я пристрою саме TX12 MKII та ваша збірка EdgeTX, реальні таймінги USB (затримки, джитер звітів), реальна поведінка при вихідній RF (період мікшера), Advanced-режим, EMI/кабель, реальну втрату USB під навантаженням. `FakeEvdevModule` це SYNTH. Перше, що перевірити на радіо: `evtest /dev/input/eventN` (імена осей, мін/макс/центр, vendor:product), далі `bench/tx12_bridge.py --input sweep`, потім `--input evdev` без гвинтів.
