# SIM-FETCH: `build/lib/fetch.sh` проти справжнього `curl` (loopback, без зовнішньої мережі)

Стан на 2026-10-03. Теги: **REPO** (виконано/перевірено в цьому репозиторії, є команда), **INF** (висновок), **UNVERIFIED** (не перевірялось), **SYNTH** (модель, не вимір).

## 1. Навіщо
`tests/static/fetch.sh` підміняє завантаження шимом `cp` (`GS_FETCH_CMD`), тому командний рядок `curl`, TLS, редиректи, HTTP-помилки, обрив і зависання з'єднання, сигнали й проксі лишалися неперевіреними (`docs/REPRODUCIBLE-BUILD.md` §5, `docs/SIM-FUZZ.md`: «`fetch.sh` з реальним `curl` не перевірено»). Цей шар ганяє **типове завантаження `fetch_file` (curl 8.5.0, OpenSSL 3.0.13, REPO: `curl --version`)** проти детермінованого локального HTTPS-сервера. Мережа: лише `127.0.0.1`; хостові `*_proxy` змінні зачищаються (результат не залежить від середовища).

## 2. Запуск
```
tests/sim/netfetch/run.sh --check      # швидко: ~11 с, 74 тести (2 пропущено: лише --long), 9 паралельних шардів
tests/sim/netfetch/run.sh --long       # +повні ланцюги ретраїв, «сплеск і тиша», 250 випадкових сценаріїв: ~70 с
tests/sim/netfetch/run.sh --check -v   # по-тестово
tests/sim/netfetch/mutate.sh           # 27 мутацій fetch.sh на КОПІЇ (~1,5 хв); mutate.sh N01 N06 -- вибіркові
```
Код виходу: 0 успіх, 1 збій, 77 пропущено (немає `python3`, `curl`, `openssl` або `sha256sum`). Змінні: `PY`, `NETFETCH_REPO` (корінь репозиторію для тесту; `mutate.sh` вказує на копію), `NETFETCH_SEED`, `NETFETCH_ITERS`, `NETFETCH_MUT_JOBS`. Працює без root (перевірено як `nobody` на повній копії, REPO).

Файли: `tests/sim/netfetch/{run.sh, test_netfetch.py, netserver.py, mutate.sh, mutations.py}`.

## 3. Фікстура (`netserver.py`, лише stdlib + `openssl` CLI)
Слухачі на `127.0.0.1:<ефемерний порт>`: `https` (сертифікат тестового CA), `selfs` (самопідписаний, ніхто не поручається), `plain` (http; сервер лише для доказу, що **жоден** запит на нього не дійшов), додатково `wrongname` (CA-сертифікат на `other.invalid`), `expired` (термін дії 2000-01-01..02), `old` (TLS ≤ 1.1), CONNECT-проксі (лише loopback-цілі). Тестовий CA передається curl через `CURL_CA_BUNDLE`: це якір довіри, а не вимкнення перевірки (клієнт без цього CA відхиляє сервер: тест `test_ca_signed_certificate_accepted_only_with_its_ca`). Сертифікати генеруються на льоту (ECDSA P-256, 2 доби), у репозиторії ключів немає.

Поведінка за шляхом: `/ok`, `/empty`, `/big` (4 МіБ псевдовипадкових байтів із фіксованим зерном), `/files/*`, `/status/<код>`, `/flaky500` (перший запит 500), `/redir?code=&to=`, `/hop/<n>` (ланцюг редиректів 301/302/307/308), `/loop`, `/drop` (обіцяє 1 МіБ, віддає 64 КіБ, закриває сокет), `/drop-once` (перша спроба обривається посеред тіла, друга повна), `/drop-chunked` (chunked без завершального чанка), `/hold` (64 КіБ і тиша), `/hold-body` (заголовки без тіла), `/hold-hdr` (прийняв запит і мовчить), `/trickle` (1 байт на 0,2 с). Кожен запит логується; лічильники ключуються повним шляхом із унікальним `?t=<тег тесту>`.

## 5. Знайдені дефекти (fuzz-стиль, виправлено у `build/lib/fetch.sh`; доказ — версія до змін, `git show HEAD:build/lib/fetch.sh`)
Усі відтворені проти початкової версії тим самим сервером (REPO). Позначення N1..N11 (щоб не плутати з D1..D22 у `docs/SIM-FUZZ.md`).

**N1. `~/.curlrc` з `insecure` вимикає перевірку TLS** (середня: потрібен файл у `$HOME`/`$CURL_HOME` користувача, що збирає). `curl` без `-q` читає `.curlrc`:
```
HOME=$H (де $H/.curlrc = «insecure»)  fetch_file https://127.0.0.1:<selfs>/ok out <sha>   ->  rc=0, файл створено (самопідписаний сертифікат прийнято)
```
Виправлення: перший аргумент `-q`.

**N2. URL-аргумент, що починається з `-`, розбирається як опція curl** (низька: URL береться з `versions.env`, INF). `fetch_file '-K/tmp/k.cfg' out <sha>` із `k.cfg` = `insecure` + `url = "https://…selfs/ok"` → `rc=0`, файл із самопідписаного сервера. Виправлення: `--url "$url"`.

**N3. Призначення, що починається з `-`, дає ХИБНИЙ УСПІХ** (середня): `cd d; fetch_file https://…/ok -n <sha>` → stdout `fetch: ok -n sha256=` (порожній хеш!), **rc=0**, файлу немає, лишається `-n.part.<pid>`; stderr: `rm: invalid option -- 'n'`, `sha256sum: invalid option -- 'n'`, `mv: invalid option -- '.'`. Виправлення: `--` у `rm`/`mv`, хеш зі stdin.

**N4. Ім'я призначення з `\` або переведенням рядка ламає перевірку хешу** (низька): `\` → у виводі `sha256=\d1c4…` (з хибним префіксом); `\n` у імені → `sha256 MISMATCH … got \d1c4…; file removed` для ПРАВИЛЬНОГО файлу (він видаляється). Причина: `sha256sum FILE` екранує такі імена, а `sha256sum -c` розбирає рядок. Виправлення: `sha256sum < "$tmp"` і порівняння рядків.

**N5. Призначення-каталог: rc=0 «ok», файл опиняється всередині каталогу під тимчасовим іменем** (низька): `fetch_file URL dir/ …` → `dir/dir.part.<pid>`. Також `mv -f` замінив би `/dev/null` або FIFO. Виправлення: призначення, що існує й не є звичайним файлом, відхиляється (rc 2); збій `mv` тепер дає rc 1.

**N6. Завислий сервер вішає збірку назавжди** (середня: щойно `--retry 3` не рятує): із `curl` лише з `--connect-timeout 20` сервер, що прийняв з'єднання й мовчить, тримає `fetch_file` без кінця (`/hold`: через 60 с `subprocess.TimeoutExpired`, процес живий). Виправлення: `--speed-limit 1 --speed-time ${GS_FETCH_STALL_SECS:-60}` (повільне, але прогресуюче завантаження не зачіпається; зависання ретраїться як таймаут).

**N7. Обрив з'єднання посеред тіла НЕ ретраїться** (середня: `--retry 3` створює хибне враження стійкості): `/drop-once` → `curl: (18) transfer closed with 2097152 bytes remaining to read`, `rc=1` після **одного** запиту. Виправлення: curl 18/52/56 ретраїться в bash (до `GS_FETCH_RETRY`, пауза 2 с); не залежить від `--retry-all-errors` (потрібен curl ≥ 7.71; Ubuntu 20.04 має 7.68, INF).

**N8. Сигнал лише bash-процесу не обробляється, доки не завершиться `curl`** (межа D13, яку називали раніше; насправді з N6 це «ніколи»): bash відкладає trap до завершення ПЕРЕДНЬОПЛАНОВОГО дочірнього процесу. Вимір до змін: `kill -TERM <pid bash>` під час `/hold` → через 4 с процес живий; після `kill -9` лишається `o.part.<pid>`. Сигнал групі працював. Виправлення: завантаження запускається фоновим завданням і `wait`; обробник сам зупиняє curl (TERM), видаляє `.part`, знімає trap-и й повторно надсилає сигнал (`rc = −сигнал`). Лишається незмінним: SIGKILL не перехоплюється (§7).

**N9. Не ідемпотентний: наявний файл із правильним хешем завантажується знову** (дизайн, низька): 1 запит замість 0; без мережі повторний запуск збірки падав, хоча файл уже перевірений. Виправлення: файл із пінoм-хешем лишається (`fetch: ok <dest> sha256=<h> (already present)`), без запиту. Без піна (`GS_ALLOW_UNPINNED=1`) поведінка не змінилась.

**N10. Невдале завантаження лишає старий НЕДОВІРЕНИЙ файл** (низька): наявний `stale` (не той хеш) + 404 → `rc=1`, `stale` на місці (виклик без `set -e` міг його використати). Виправлення: файл із хибним хешем видаляється до завантаження (з попередженням `WARNING … removed, downloading again`).

**N11. Без піна `GS_FETCH_CMD`, що повернув 0, але не створив файлу, дає rc=0** (низька): `GS_ALLOW_UNPINNED=1 GS_FETCH_CMD=true fetch_file x out ""` → `sha256sum: …No such file`, `computed sha256: ` (порожній), **rc=0**. Виправлення: rc 1, `download … reported success but produced no file`.

Додатково (профілактика): ім'я тимчасового файлу тепер `.part.${BASHPID:-$$}` (паралельні субоболонки одного скрипта мають спільний `$$`); невалідні `GS_FETCH_RETRY`/`GS_FETCH_STALL_SECS` дають rc 2 до будь-якої дії.

### Зміни поведінки (для рев'ю)
- Нові змінні: `GS_FETCH_RETRY` (за замовч. 3), `GS_FETCH_STALL_SECS` (за замовч. 60); обидві валідуються (`^[0-9]+$`, `^[1-9][0-9]*$`).
- `-q`: `.curlrc` більше не діє; проксі й CA задавати змінними середовища (`https_proxy`, `CURL_CA_BUNDLE`), які **діють**.
- Файл із правильним хешем не завантажується повторно (N9); файл із хибним хешем видаляється ще до завантаження (N10).
- `tests/golden/static/fetch.out` **не змінився** (`diff <(tests/static/fetch.sh 2>&1) tests/golden/static/fetch.out`, REPO). Довелося оновити два патерни мутацій у `tests/sim/fuzz/mutations.py` (M15, M16), бо вони шукали точні рядки старого коду (`sha256sum -c`, виклик `_gs_curl_fetch`); обидві й M52..M54 далі вбиваються.

**Еквівалентний мутант (не вбивається, чесно).** Ослаблення лише `--proto-redir` (`'=all'`) нічого не змінює: libcurl 8.5.0 перевіряє дозволені протоколи (`--proto '=https'`) на кожному хопі, тож `--proto-redir` дублює `--proto` (REPO: мутант виживав у `TestRedirects`). Обидва прапорці лишено (глибинна оборона); N10/N11 послаблюють їх разом, що й є реалістичною регресією.

## 7. Межі й UNVERIFIED
- **SIGKILL** не перехоплюється: `.part.<pid>` лишається (тест `test_sigkill_limit` фіксує межу), `curl` осиротіє. Прибирання застарілих `*.part.*` попередніх запусків не робиться.
- Базове ім'я призначення > ~240 символів легальне, але недосяжне: `имя + ".part.<pid>"` перевищує `NAME_MAX` (255); `fetch_file` завершується rc 1 без залишків (тест `…too_long…`).
- Мінімум TLS 1.2 перевірено лише за умови, що OpenSSL можна послабити через `OPENSSL_CONF` (контроль у тесті); на збірці OpenSSL, де це неможливо, тест пропускається, а гарантію дає статична перевірка прапорця. Максимум/шифри/OCSP/відкликання сертифікатів не перевірялись.
- **UNVERIFIED (не перевірялось):** реальні сервери й реальний GitHub (`github.com`, `raw.githubusercontent.com`, `ftp.cn.debian.org`; сесія має політику мережі з 403, піни порожні); DNS, IPv6, HTTP/2 і HTTP/3, ALPN, CDN-редіректи з відносними/дуже довгими `Location`, дрейф годинника; блокований/«чорна діра» `connect` (`--connect-timeout 20` на loopback неможливо відтворити); поведінка інших версій curl (7.74 на Debian 11, 7.81 на Ubuntu 22.04, 8.x): тут лише 8.5.0; захист від кількох **процесів**, що пишуть одне призначення (атомарність `mv` — INF, одну гонку перевірено лише між субоболонками одного скрипта); `git_pin` по https (лише `file`/локальний репозиторій у `tests/static/fetch.sh`); поведінка `fetch_file` у `build/build.sh` (хелпери досі не підключені, `docs/REPRODUCIBLE-BUILD.md`).
- Тести вимагають `python3`, `curl`, `openssl` CLI, `bash`, `sha256sum`, `awk`, `/proc` (пошук осиротілих curl); без них `run.sh` повертає 77.
